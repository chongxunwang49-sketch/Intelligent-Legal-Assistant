## 1. 项目概述

### 1.1 背景与定位
法律行业合同纠纷案件量大、企业法务审查能力有限，传统人工审查一份 20 页合同需 45~90 分钟。
智法通面向企业法务总监、执业律师、中小企业主三类用户，用**本地化大模型 + 两阶段 RAG + 法律知识图谱 + 多 Agent 对抗式审查**，把法律咨询与合同审查从"人工经验依赖"变为"可审计、可解释、可回溯的工程化流程"，核心价值是**降低法律幻觉、压缩审查时间、提升风险召回率**。

### 1.2 项目目标
1. 提供带**法条引用**与**置信度**的法律智能问答（本地化、可离线、合规）。
2. 提供**多 Agent 对抗式**合同风险审查（主审/复核/反方/仲裁），30 秒级初审，风险可解释。
3. 建立法律知识库（法规/案例）与 **Neo4j 语义图谱**，支持 **GraphRAG 三路融合检索** 与 **时间旅行版本查询**。
4. 提供数据分析看板、RBAC 权限、额度控制、审计留痕，满足企业级与合规要求。

### 1.3 关键名词
- RAG：检索增强生成；RRF：倒数排名融合；BM25：稀疏检索；ANN：近似最近邻（Chroma HNSW）
- Self-RAG：LLM 对自身回答做质量自评估并在低置信时触发重检索
- MCP：Model Context Protocol（工具标准化协议）
- LangGraph：基于图的工作流编排框架

## 4. 系统架构

### 4.1 总体架构
```
用户/前端(Vue3 + Element Plus + ECharts)  ── nginx(:8188，SSE 反代)
        │ /api/v1
FastAPI 后端(:8000→28000)
  ├─ api      认证/问答/合同/知识库/图谱/分析/仪表盘/通知/用户管理
  ├─ services 业务服务（额度、通知、问答、合同、知识库、图谱、分析）
  ├─ agent    LangGraph 12 节点对抗式合同审查 + 工具
  ├─ rag      query_rewriter/sub_query/self_eval/pipeline/retriever/reranker/embedding/vector_store
  ├─ mcp_servers  MCP 工具服务器（官方 mcp 2.x MCPServer）
  └─ models   SQLAlchemy 16 张表
基础设施：MySQL8(:13306) · Redis7(:26379) · Neo4j5(:17474/17687) · Chroma
模型服务：Ollama qwen2.5:1.5b + bge-large-zh-v1.5（宿主机 11434）· rerank bge-reranker-v2-m3（宿主机 9999）
```

### 4.2 技术栈
FastAPI + SQLAlchemy 2.0(asyncmy) + Redis + ChromaDB + Neo4j 5 + LangGraph + MCP SDK
qwen2.5:1.5b(Ollama) · bge-large-zh-v1.5 · bge-reranker-v2-m3
Vue3 + TypeScript + Vite + Element Plus + Pinia + ECharts · Docker Compose + Nginx

### 4.3 检索管线（两阶段 + GraphRAG）
```
问题 → 指代消解/改写 → (复杂?) 子查询分解
   ├─ 稠密：Chroma ANN(bge-large-zh-v1.5,1024)
   ├─ 稀疏：BM25（jieba）
   └─ 图谱：Neo4j 概念→法条 / 法名→案例（GraphRAG）
  → RRF 融合(稠密+稀疏) + 图谱候选 → Cross-Encoder 精排 Top-5 → LLM 生成
  → Self-RAG 6 维自评估 → 需修订？重检索改写 ≤2 轮 → 法条引用校验/免责声明
```

### 4.4 知识图谱 Schema（Neo4j）
- 节点：Law / Article / Case / Concept / PartyType
- 关系：HAS_ARTICLE / MENTIONS / REFERENCES{role:APPLIES|CITES|OVERRULES} / INVOLVES / RELATES{type} / INVOLVES_PARTY
- 约束：Law.name、Article.node_id、Case.node_id、Concept.name、PartyType.name 唯一

### 4.5 合同审查工作流（LangGraph 12 节点）
parse_doc → split_clauses → completeness_check → classify_clauses → risk_detect →
compliance_check → consistency_check → **adverse_attack** → **debate** →
risk_score → suggestions → report_generate
输出：风险条款/风险等级/综合评分/三维度健康分/对抗意见/辩论日志/待协商事项/修订建议。

### 4.6 安全设计
- JWT(HS256, type=access/refresh)、bcrypt；RBAC 三级（superuser>legal_admin>权限码）
- 登录防爆破：Redis 失败 5 次锁 30 分钟；XSS 净化统一；上传扩展名/MIME/大小校验；越权归属校验
- 额度：Redis 原子计数（qa 50/日、contract 10/日，admin 豁免）
- 合规：《生成式 AI 服务管理暂行办法》免责声明、最小化收集
