# 智法通 V2 · 部署手册

## 1. 环境要求
- Windows 11 + Docker Desktop（Linux 容器模式，已运行）
- Python 开发/运维用 conda base（后端依赖）与 pytorch 环境（rerank 精排）
- 宿主机服务（Docker 之外独立运行）：
  - **Ollama** http://localhost:11434：模型 `qwen2.5:1.5b`、`quentinz/bge-large-zh-v1.5:latest`
  - **rerank 精排** http://localhost:9999（见 §3）

## 2. 端口规划
| 服务 | 容器内 | 宿主机 |
|---|---|---|
| MySQL | 3306 | 13306 |
| Redis | 6379 | 26379 |
| Neo4j | 7474/7687 | 17474/17687 |
| 后端 FastAPI | 8000 | 28000 |
| 前端 Nginx | 80 | 8188 |
| rerank（宿主） | — | 9999 |
| Ollama（宿主） | — | 11434 |

## 3. 准备外部模型服务
```bash
# Ollama（Windows 原生安装后）
ollama pull qwen2.5:1.5b
ollama pull quentinz/bge-large-zh-v1.5:latest

# rerank 精排（首次自动下载 BAAI/bge-reranker-v2-m3 ≈1.1GB，走 HF 镜像）
cd rerank_service
HF_ENDPOINT=https://hf-mirror.com python server.py   # 监听 0.0.0.0:9999
```
健康检查：`curl http://localhost:9999/health` → `{"status":"healthy","ready":true}`

## 4. 一键部署（生产）
```powershell
# 项目根目录
.\scripts\start.ps1
```
或手动：
```bash
cp .env.example .env        # 按需修改端口与密钥
docker compose up -d --build
```
首次启动自动完成：建库 → ORM 建表(16) → 幂等种子(3 角色/3 账号/法规与案例/演示合同/模拟分析) →
Chroma 向量索引 → Neo4j 知识图谱构建。启动较慢，可用：
```bash
docker compose logs -f backend   # 观察初始化
docker compose ps                 # 全部 healthy 即可
```

## 7. 常用运维
```bash
docker compose down          # 停止（保留数据卷）
docker compose down -v       # 全清重建（含数据）
docker compose up -d         # 重启
docker compose logs -f backend|frontend|neo4j
# 重建图谱（Neo4j 数据异常时）
curl -X POST http://localhost:28000/api/v1/graph/rebuild -H "Authorization: Bearer <admin-token>"
```

## 8. 故障排查
| 现象 | 处理 |
|---|---|
| 后端启动重试等待 DB | 等待；MySQL 健康后再启 |
| 问答无引用（降级） | 检查 Ollama `curl http://localhost:11434/api/tags`、rerank 9999 健康 |
| 图谱数据为空 | `POST /graph/rebuild` |
| 端口占用 | `.env` 改端口后重启 |
| GitHub 推送超时 | 本机代理 `git config http.https://github.com/.proxy http://127.0.0.1:7897` |
